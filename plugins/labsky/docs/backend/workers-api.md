# APIs and Server Code on Cloudflare Workers

> Read when writing server-side code that runs on a Worker: a site's server functions and loaders, a call to another service, or a standalone API.

Sections that come from a Labsky project cite it. Sections marked **Proposed** have no Labsky project behind them yet: follow them, and when the first project uses them, confirm or correct the doc in the same PR.

---

## Server-only configuration

Source: `ciudad-ilamapa` (`src/config/server-env.ts`).

- Public configuration (`VITE_*`) lives in `src/config/env.ts` (`docs/frontend/env-and-config.md`). **Anything secret never carries `VITE_`**: Vite inlines those into the browser bundle.
- Server-only values (an API key, a service URL) are parsed with Valibot in `src/config/server-env.ts`, which only server code imports.
- Decide explicitly what happens when a value is missing, and make it loud: without a service URL the site serves its fallback content and logs it; without a key, the action fails with a visible error and a server log. **Never a pretend success.**
- On a Worker, secrets are set with `wrangler secret put` by a human and public values go in `vars` in `wrangler.jsonc` (`docs/infra/cloudflare.md`).

## Calling another service

Source: `ciudad-ilamapa` (`src/lib/cms.lib.ts`, `src/data/cached-content.util.ts`).

- **One client per service** in `src/lib/<service>.lib.ts`. Nothing else talks to that service. On Workers it is a thin `fetch` wrapper, not Axios (the project's `CLAUDE.md` records this override of `docs/frontend/api-layer.md`).
- **Worker to Worker goes through a Service Binding** (`services` in `wrangler.jsonc`), reached with `env.<BINDING>.fetch(request)`: no trip over the internet, and no public route needed. In local development, where the other service is not a Worker, the client falls back to its URL.
- The client throws a typed error on a non-OK status (`class CmsError extends Error { status }`). Services call the client and **validate every response with Valibot** before returning it.
- **Server functions sit between queries and services** in TanStack Start: a query's `queryFn` calls a server function, so the service and its key are only ever reached from the server.
- **Content the page depends on is read through a cache with a timeout and a fallback**: a validated copy is served for a few minutes, the request gives up after a few seconds, after a failure the service is left alone for a while, and the visitor gets the last good copy or, without one, the fallback content. Every fallback is logged with its reason (`docs/infra/observability.md`).
- Requests that write (a lead, a turn) are never cached and never retried blindly: the service decides idempotency.

## Standalone APIs (**Proposed**)

For an API that is its own Worker (not a CMS, not a site's server functions):

- **Framework: Hono.** It is built for Workers, typed end to end, and small. Its app is typed with the Worker's bindings: `new Hono<{ Bindings: Env }>()`, with `Env` generated by `wrangler types`.
- **Layout**, in `src/`:

  | Folder | Suffix | Holds |
  |---|---|---|
  | `routes/` | `.route.ts` | One Hono router per resource, mounted in `index.ts` |
  | `handlers/` | `.handler.ts` | Parse and validate input, call a service, shape the response |
  | `services/` | `.service.ts` | Business logic and data access; no HTTP types |
  | `schemas/` | `.schema.ts` | Valibot schemas for every input and output |
  | `config/` | `env.ts` | Validated configuration |
  | `lib/` | `.lib.ts` | Clients for other services |

- **Validate at the edge**: every body, query and param is parsed with Valibot in the handler before anything else runs. A failed parse answers `400` with the flattened issues.
- **One error envelope**: `{ "error": { "code": "not_found", "message": "…" } }`, with a matching status. Unknown errors answer `500` with a generic message and are logged with their cause; internals never reach the response.
- **Authentication**: Worker-to-Worker callers come through a Service Binding and need no public auth. External callers send an API key in `Authorization`, compared in constant time against a Worker secret. Per-user auth is its own design decision, escalated to a human.
- **Rate limiting** on any public write endpoint, with Workers' rate limiting binding, keyed by the caller.
- **CORS** is closed by default. Open it only for named origins, never `*` on an endpoint that reads cookies or keys.
- Workers run on V8, not Node: use `nodejs_compat` for the Node APIs a library needs, and avoid anything that needs a filesystem.

## Testing

- Pure logic (`utils/`, services with injected clients) is unit-tested with Vitest.
- Response validation is tested with a recorded response that passes and one that fails.
- **Proposed**: route-level tests for standalone APIs with `@cloudflare/vitest-pool-workers`, which runs them in workerd with local bindings.
